Bash для специалиста по ИБ

Командная строка как инструмент аудита и расследования

Две лабораторные: основы → анализ логов → расследование

Зачем безопаснику bash

  • на серверах нет графического интерфейса — только терминал
  • логи — это текст; текст — родная стихия bash
  • при инциденте GUI-инструменты могут быть недоступны или заражены; штатные команды — всегда под рукой
  • рутина (проверки, отчёты, мониторинг) автоматизируется скриптами

Сегодня: от ls — до обнаружения взлома в логах.

Как выполняется команда

вы вводите
→
shell (bash)
разбирает
→
программа
работает
→
stdout / stderr
  • stdout — обычный вывод, stderr — ошибки (поток №2)
  • команда возвращает код завершения: 0 — успех, не 0 — ошибка
  • вывод одной команды можно передать другой — это конвейер |

Часть 1. Основы

Навигация, права, пользователи, поиск, процессы, история

Навигация и скрытые файлы (task01)

pwd            # где я
cd data/practice_tree
ls -la         # всё, включая скрытое
  • файлы с точки в начале (.env) обычный ls не показывает
  • там часто лежат пароли и настройки — а иногда и «закладки»
  • cd .. — уровень вверх, cd ../.. — два

В задании найдёте скрытый файл с паролем — и поймёте, почему .env не коммитят.

chmod 600 .env = владелец rw (4+2), остальным — ничего. chmod 777 — все могут всё. Так не делаем никогда.

Пользователи (task03)

whoami   # кто я
id       # мои UID/GID и группы
  • все пользователи — в /etc/passwd: имя:x:UID:GID:...:shell
  • UID 0 — root, всемогущий. Обычные люди — UID ≥ 1000
  • при аудите проверяют: нет ли «лишнего» пользователя с UID 0 — классическая закладка

find и SUID (task04)

find dir -name "*.log"     # по имени
find dir -type d           # только каталоги
find dir -mtime -1         # изменены за сутки
find /usr/bin -perm -4000 2>/dev/null   # SUID
  • SUID: программа выполняется с правами владельца (например root), а не запустившего
  • легитимно: passwd. Лишний SUID — готовое повышение привилегий
  • поэтому атакующий первым делом делает именно этот find — и защитник должен делать его регулярно

grep (task05)

grep "Failed password" auth.log        # строки с шаблоном
grep "Failed password" auth.log | wc -l  # сколько их
grep -v "192.168.1" ...                  # инверсия: всё КРОМЕ
grep -oE 'from [0-9.]+' ...              # вырезать кусок
  • grep — главный инструмент чтения логов
  • | wc -l превращает поиск в число: «сколько раз» важнее «вижу строки»

Процессы (task06)

ps aux | grep sleep     # найти процесс
kill               # вежливо завершить (TERM)
kill -9            # убить безусловно (KILL)
  • вредонос на машине — это процесс; ps aux — кто живёт в системе
  • KILL не даёт процессу «прибраться» — при расследовании иногда вредно: не успеем снять улики из памяти

Перенаправления (task07)

команда >  out.txt    # записать (перезаписать файл!)
команда >> out.txt    # дописать в конец
команда 2> err.txt    # только ошибки
команда > out.txt 2>&1  # всё в один файл

Для безопасника это — фиксация улик: каждый шаг расследования пишется в файл-отчёт, а не «я видел в консоли».

history как улика (task08)

  • history — журнал команд пользователя; взломщик его боится
  • обходы: history -c, команда с пробелом впереди (работает при HISTCONTROL=ignorespace)
  • вывод защитника: history — улика, но подчищаемая; настоящий аудит — логи, которые уходят на сервер, недоступный атакующему

В задании разберёте историю «гостя»: что скачал, что читал, как заметал следы.

Часть 2. Логи и скрипты

Конвейеры, awk, обнаружение атак, автоматизация

Философия конвейеров

Маленькие программы, каждая делает одно дело, склеиваются через |:

cut -d' ' -f1 access.log | sort | uniq -c | sort -rn | head -5
 │ вырезать IP   │ рядом │ посчитать │ по убыванию │ топ-5

Собирайте конвейер по одной команде, глядя на вывод после каждой — так делают все.

Важно: uniq -c склеивает только СОСЕДНИЕ строки — поэтому sort перед ним обязателен.

awk: колонки и фильтры (task02)

awk '{print $1}' access.log          # первая колонка (IP)
awk '{print $9}' access.log          # девятая (HTTP-код)
awk '$9 == 404' access.log           # фильтр: только 404

awk читает файл построчно и сам режет на поля по пробелам. Формат: условие {действие} — любое из двух можно опустить.

Читаем auth.log (task03)

Nov 19 14:00:45 server sshd[3335]: Failed password for admin from 198.51.100.23 port 51505 ssh2
Nov 19 14:01:51 server sshd[3399]: Failed password for invalid user root from 203.0.113.7 ...
  • подвох: invalid user добавляет два слова → номер колонки с IP «плывёт»
  • надёжно: резать по маркеру from, а не по номеру поля: grep -oE 'from [0-9.]+' | awk '{print $2}'

Урок на всю карьеру: не доверяйте формату лога — проверяйте.

Читаем access.log (task04)

192.168.1.15 - - [19/Nov/2026:10:12:33 +0300] "GET /products HTTP/1.1" 200 4521
 │поле 1 (IP)                     поле 6-8 (запрос)      │код(9) │байты
  • распределение кодов — «пульс» сайта: awk '{print $9}' | sort | uniq -c
  • серия 404 по /admin, /.env, /.git — сканер ищет уязвимости
  • машинный темп (запросы каждые секунды) выдаёт автоматику

Окно времени (task05)

grep "Nov 19 14:" auth.log          # весь 14-й час
grep "Nov 19 14:[3-5]" auth.log     # 14:30–14:59
  • расследование = сужение: сначала «весь день», потом час, потом минуты
  • скобки [3-5] — «один символ из набора»

Скрипты (task06)

#!/usr/bin/env bash
set -euo pipefail        # падать при ошибке, не «ехать дальше»
LOG="${1:-data/auth.log}"  # аргумент со значением по умолчанию
  • скрипт = записанные в файл команды + chmod +x
  • $1 — первый аргумент; :- — «если не передали, возьми вот это»
  • всё, что делали руками в lab1–lab2, превращается в report.sh

Этика

  • все приёмы отрабатываем на своих файлах и своём стенде
  • те же команды против чужих систем без разрешения — уголовная статья
  • мы учимся защищать: находить следы, доказывать, укреплять

Итоги

  • сервер безопасника — это терминал и текстовые логи
  • права, пользователи, процессы — то, что аудируется в первую очередь
  • конвейер grep/awk | sort | uniq -c | sort -rn решает 80% разбора логов
  • ручные команды → скрипт → автоматический мониторинг
  • вывод без команды-доказательства — не вывод
