# Задание 8. История команд как улика

**Что делаем:** изучаем `history` — журнал команд пользователя,
и как его (пытаются) замести.

## Шаг 1. Ваша история

```bash
history | tail -10
```

Всё, что вы вводили в этой сессии.

## Шаг 2. Повторение команды из истории

```bash
history | grep ssh
!42        # выполнить команду №42 — ВПИШИТЕ реальный номер из своего вывода
```

## Шаг 3. Анализ «чужой» истории

В папке `data/` лежит `intruder_history.txt` — история команд
пользователя, который побывал на «сервере». Прочитайте и ответьте:

1. Что он скачивал и откуда?
2. Какой файл он пытался прочитать с паролями?
3. Какой командой он замёл следы? Сработает ли это против внимательного
   администратора?

## Шаг 4. Способ попроще: пробел

```bash
echo "эта команда попадёт в history"
 echo "а эта — с пробелом впереди — нет"
history | tail -3
```

Проверьте, попала ли вторая команда в историю (зависит от настройки
HISTCONTROL — на многих системах команда с пробелом впереди
не логируется).

## Результат

**В отчёт:** ответы на три вопроса шага 3 и наблюдение из шага 4.

> Вывод для защитника: история — улика, но недостаточная: её можно
> подчистить. Настоящий аудит — это логи, которые уходят на сервер,
> недоступный атакующему.
